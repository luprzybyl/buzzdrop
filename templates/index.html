How it works

Three steps, and nothing left behind.

1

Encrypt before upload

Pick a file or write a note, set a password, and the browser seals it with AES-GCM locally.

2

Share the one-time link

Send the link, and send the password somewhere else. Two channels, one drop.

3

Watch it self-destruct

The file is deleted the moment the recipient continues — before the password is even checked.

What’s guaranteed

Four things you can rely on — each of them checkable in the source.

The server never sees your key

Your password derives half the key in the browser via PBKDF2 — 600,000 iterations — and never leaves the device. The other half is a server-held share released exactly once, so a stolen ciphertext alone is dead bytes. Buzzdrop stores ciphertext and metadata; it cannot read the drop.

Continuing spends the drop

Once the recipient confirms, the file is deleted before a password is even entered. A wrong guess gets no second attempt, and neither does anyone who finds the link later.

An expiry is a hard cut-off

Give a drop a deadline and the link stops working once it passes. The attempt is refused and the copy swept away — whether or not anyone ever opened it.

You find out it happened

Buzzdrop records when the drop was fetched and from which IP, and can email you once, the moment the recipient attempts decryption.
